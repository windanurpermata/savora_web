BAB I
PENDAHULUAN

1.1 Latar Belakang

Perkembangan teknologi berbasis web saat ini telah mengubah lanskap pertukaran informasi secara signifikan. Savora Web hadir sebagai platform berbagi resep kuliner modern yang memungkinkan koki (Chef) mempublikasikan kreasi kuliner mereka dan anggota (Member) untuk mencari, menandai (Bookmark), serta memberikan rating pada resep. Sebagai platform interaktif yang mengelola data pengguna, resep, dan ulasan, Savora Web menuntut fondasi keamanan yang tangguh guna menjamin kerahasiaan (Confidentiality), integritas (Integrity), dan ketersediaan (Availability) data.

Permasalahan keamanan pada aplikasi web terus meningkat seiring berkembangnya metode penyerangan. Berdasarkan daftar OWASP Top 10 terbaru, kerentanan seperti Broken Access Control (Kegagalan Kontrol Akses) dan Injection (Injeksi) tetap menduduki peringkat teratas sebagai ancaman kritis. Dalam konteks aplikasi Savora Web, kegagalan dalam pembatasan otorisasi dapat berdampak fatal, misalnya seorang Member biasa dapat memodifikasi atau menghapus resep milik Chef lain, atau bahkan mengakses panel kontrol administratif (Admin Dashboard).

Selain masalah otorisasi, keamanan basis data memegang peranan krusial. Basis data menyimpan informasi sensitif seperti kredensial akun pengguna, alamat email, serta data transaksi resep. Tanpa perlindungan terstruktur, basis data rentan terhadap serangan SQL Injection (SQLi). Serangan ini terjadi ketika data masukan pengguna yang tidak divalidasi langsung disatukan ke dalam query SQL dinamis, memungkinkan penyerang mengeksekusi perintah database yang tidak sah untuk membaca, memanipulasi, atau menghapus data.

Pilar penting lainnya dalam sistem keamanan adalah Manajemen Identitas (Identity Management). Identitas pengguna harus dipastikan keabsahannya sejak proses registrasi hingga autentikasi. Tanpa pembatasan login, aplikasi rentan terhadap serangan Brute Force dan Credential Stuffing, di mana penyerang secara otomatis mencoba ribuan kombinasi password untuk meretas akun. Oleh karena itu, penerapan kebijakan kata sandi yang kuat, pembatasan jumlah percobaan login (Rate Limiting), verifikasi email, serta autentikasi berbasis tantangan matematika (CAPTCHA) menjadi hal wajib guna menjaga integritas platform Savora Web dari penyalahgunaan.

1.2 Rumusan Masalah

Berdasarkan latar belakang di atas, rumusan masalah dalam implementasi keamanan ini adalah:

  1. Bagaimana merancang sistem autentikasi multi-role yang aman dari serangan brute-force dan otomatisasi registrasi palsu pada Savora Web?
  2. Bagaimana mencegah eksploitasi celah SQL Injection dan Insecure Direct Object References (IDOR/BOLA) pada query basis data aplikasi?
  3. Bagaimana mengimplementasikan Role-Based Access Control (RBAC) dan pengamanan level administratif yang membatasi hak akses berdasarkan IP (IP Whitelisting) dan level administratif?

1.3 Tujuan

Tujuan yang dicapai melalui kegiatan implementasi keamanan ini adalah:

  1. Membangun modul autentikasi yang dilengkapi dengan pembatasan percobaan login (Rate Limiting 3 kali, lockout 5 menit) dan verifikasi CAPTCHA matematika.
  2. Menerapkan arsitektur data access secure query memanfaatkan Eloquent ORM berbasis parameterized query untuk menjamin imunitas terhadap SQL Injection.
  3. Membangun middleware otorisasi berbasis hak akses peran (Member, Chef, Admin, Super Admin) dan membatasi akses khusus panel admin hanya dari alamat IP localhost tepercaya (127.0.0.1 dan ::1).

BAB II
ANALISIS, PERANCANGAN DAN IMPLEMENTASI

2.1 Desain Keamanan Sistem (Autentikasi, Otorisasi)

Keamanan Savora Web dirancang menggunakan pendekatan pertahanan berlapis (defense-in-depth). Desain ini memisahkan kontrol keamanan menjadi dua fase utama, yaitu Autentikasi (pembuktian identitas) dan Otorisasi (pemberian hak akses).

A. Arsitektur Autentikasi

Alur autentikasi pada Savora Web dirancang untuk menyaring pengguna secara ketat guna menepis serangan brute force dan pendaftaran akun massal oleh bot. Fitur-fitur keamanan autentikasi yang diimplementasikan meliputi:

  • Strict Validation & Complexity: Pendaftaran akun baru mewajibkan parameter email yang unik dan password yang memenuhi standar kompleksitas minimal 8 karakter, wajib memiliki huruf besar, huruf kecil, angka, dan karakter simbol spesial.
  • CAPTCHA Matematika: Setiap formulir login dan register dilengkapi dengan CAPTCHA dinamis berbasis matematika penjumlahan angka acak (1-20) yang disimpan dalam session server untuk menghindari bypass bot otomatis.
  • Rate Limiting (Lockout): Pada controller login (`LoginController.php`), diimplementasikan pembatasan hingga maksimal 3 kali kegagalan autentikasi. Jika batas terlampaui, IP & Email tersebut akan dikunci (lockout) selama 300 detik (5 menit) menggunakan layanan RateLimiter bawaan Laravel.
  • Session Security: Setelah login berhasil, session di-regenerasi secara otomatis dengan perintah `$request->session()->regenerate()` untuk mereduksi risiko serangan Session Fixation.
  • Email Verification: User yang baru terdaftar harus memverifikasi email melalui tautan bertanda tangan kriptografis (signed URL) sebelum dapat mengakses fitur-fitur internal platform.

B. Arsitektur Otorisasi

Otorisasi diterapkan menggunakan konsep Role-Based Access Control (RBAC) dan dibantu oleh middleware keamanan kustom. Request HTTP disaring menggunakan tiga middleware utama:

  1. RoleMiddleware: Membatasi akses rute berdasarkan peran umum user (member atau chef). Jika pengguna yang tidak berhak mencoba mengakses, sistem menghentikan proses dan menghasilkan respon HTTP 403 Forbidden.
  2. AdminRoleMiddleware: Membagi otorisasi administrator menjadi 2 level: Admin Biasa dan Super Admin (diidentifikasi berdasarkan email tertentu seperti `admin@savora.com` atau penanda nama). Rute pengelolaan sensitif seperti manajemen pengguna dan kategori hanya diizinkan untuk tingkat Super Admin.
  3. AdminIpWhitelist: Menambahkan lapisan pertahanan jaringan (network layer) dengan cara menolak seluruh permintaan ke area administratif (`/admin/*`) apabila alamat IP peminta tidak terdaftar dalam whitelist (`127.0.0.1` dan `::1`).

2.2 Secure Query

Keamanan manipulasi basis data pada Savora Web dibangun dengan mengandalkan paradigma modern dari kerangka kerja Laravel Eloquent ORM. Seluruh operasi penulisan dan pembacaan query SQL diimplementasikan tanpa merangkai string secara manual (SQL string concatenation).

A. Pencegahan SQL Injection

Secara default, Eloquent menggunakan mekanisme binding parameter PDO (PHP Data Objects). Ketika query filter pencarian resep dijalankan, input pencarian dilewatkan sebagai binding parameter: 

$query->where('judul', 'like', '%' . $request->q . '%');

Mekanisme di atas menjamin bahwa nilai dari variabel `$request->q` akan selalu diperlakukan sebagai literal string, bukan sebagai bagian dari perintah sintaksis SQL yang dapat dieksekusi, sehingga menutup celah SQL Injection secara total.

B. Pencegahan Insecure Direct Object References (IDOR / BOLA)

Kerentanan IDOR (BOLA) terjadi saat pengguna dapat memanipulasi parameter ID objek untuk mengakses atau mengubah data milik orang lain. Pada Savora Web, keamanan data resep dijamin dengan menyematkan relasi kepemilikan user (`Auth::id()`) pada setiap manipulasi data (Edit, Update, Delete): 

// Menjamin hanya pemilik resep asli yang dapat mengakses form edit
$resep = Recipe::where('user_id', Auth::id())->findOrFail($id);

Dengan menyaring query berdasarkan id pengguna yang sedang login (`user_id = Auth::id()`), penyerang yang mencoba memanggil endpoint `/chef/resep/12/edit` untuk resep yang bukan miliknya akan langsung mendapatkan respons error `404 Not Found` atau `403 Forbidden` alih-alih data resep terpublikasi/dimodifikasi.

2.3 Hak Akses Database & RBAC

Model data Savora Web mengadopsi struktur relasional yang terintegrasi. Hak akses database dipetakan ke dalam bentuk kolom `role` pada tabel `users`.

Nama Tabel Deskripsi Fungsi Hak Akses Peran (CRUD)

BAB III
PENGUJIAN DAN ANALISIS KERENTANAN

3.1 Pengujian Mitigasi Brute Force & Captcha

Pengujian dilakukan untuk memverifikasi keandalan Rate Limiter dan CAPTCHA matematika pada form login. Skenario pengujian dilakukan secara berurutan dengan hasil sebagai berikut:

Skenario Uji Input yang Diberikan Hasil yang Diharapkan Status
Login dengan CAPTCHA salah Email valid, Password valid, CAPTCHA asal Ditolak, muncul pesan kesalahan CAPTCHA, session CAPTCHA di-reset ulang. Berhasil
Melakukan percobaan login gagal sebanyak 3 kali berturut-turut Email valid, Password salah, CAPTCHA benar (3x) Pada kegagalan ke-3, sistem mengunci login dan menampilkan pesan lockout selama 5 menit. Berhasil
Mencoba login pada masa lockout (detik ke-30) Email valid, Password benar, CAPTCHA benar Akses ditolak langsung tanpa memeriksa password ke database, masa tunggu ditampilkan. Berhasil

3.2 Pengujian Otorisasi & Pencegahan Bypass Akses (BOLA/IDOR)

Pengujian otorisasi ini difokuskan pada pengujian kekuatan RoleMiddleware, AdminRoleMiddleware, serta proteksi direct object reference.

  • Pengujian IP Whitelist Admin: Mengakses rute `/admin/dashboard` dari perangkat lain dalam satu jaringan lokal (IP non-127.0.0.1). Hasil menunjukkan sistem menolak akses secara instan dan melempar halaman 403 Forbidden. Akses hanya diizinkan dari mesin lokal localhost.
  • Pengujian Level Admin: Menggunakan akun Admin Biasa (misal: `admin_staf@savora.com`) untuk mengakses rute manajemen pengguna (`/admin/users`). Hasil menunjukkan sistem menolak dengan pesan "Akses khusus Super Admin" sesuai logika pada `AdminRoleMiddleware.php`.
  • Pengujian Bypass IDOR: Melakukan login sebagai `Chef A` kemudian mengirimkan HTTP request `PUT` secara paksa menuju url `/chef/resep/{id_resep_milik_chef_b}`. Hasil pengujian menunjukkan Laravel mengembalikan respon `404 Model Not Found` karena query disaring ketat menggunakan scope user terkait.

3.3 Pengujian SQL Injection

Percobaan injeksi SQL dilakukan pada kolom filter pencarian resep (`/resep?q=`). Input uji coba yang dimasukkan berupa payload SQL standar untuk membypass autentikasi atau menarik data tidak sah: 

Payload Input: ' OR '1'='1' -- 
Query Hasil Eksekusi: SELECT * FROM `recipes` WHERE `judul` LIKE '%\' OR \'1\'=\'1\' --%'

Hasil analisis menunjukkan tanda petik tunggal (`'`) otomatis di-escape oleh PDO adapter (ditandai dengan penambahan backslash `\'`). Sistem memperlakukan keseluruhan input tersebut sebagai string pencarian biasa untuk mencari judul resep yang mengandung kata ' OR '1'='1' --. Tidak ada syntax SQL tambahan yang berhasil dieksekusi, membuktikan sistem aman dari kerentanan SQL Injection.

BAB V
PENUTUP

5.1 Kesimpulan

Berdasarkan tahapan analisis, implementasi, dan pengujian keamanan yang telah dilaksanakan pada platform Savora Web, diperoleh beberapa kesimpulan sebagai berikut:

  1. Manajemen Identitas (Identity Management) pada platform Savora Web telah berhasil ditingkatkan dengan menerapkan verifikasi CAPTCHA matematika dinamis untuk menyaring bot, serta Rate Limiter login (lockout 5 menit setelah 3 kali gagal) yang terbukti ampuh mencegah serangan brute-force.
  2. Implementasi keamanan basis data menggunakan parameterized query bawaan Eloquent ORM telah menutup celah keamanan SQL Injection secara penuh. Selain itu, pembatasan query berbasis scope kepemilikan pengguna berhasil mencegah eksploitasi celah Broken Object Level Authorization (BOLA/IDOR).
  3. Mekanisme otorisasi Role-Based Access Control (RBAC) dan perlindungan panel admin dengan IP Whitelisting & klasifikasi level admin biasa/super admin terbukti efektif dalam membatasi area sensitif sistem agar hanya dapat diakses oleh pihak yang berwenang dari host tepercaya.

5.2 Saran

Meskipun sistem keamanan saat ini sudah berjalan dengan baik, terdapat beberapa saran untuk pengembangan dan penguatan aspek keamanan di masa mendatang:

  1. Implementasi Multi-Factor Authentication (MFA): Untuk akun koki (Chef) dan administrator, disarankan menambahkan autentikasi dua faktor (MFA/2FA) menggunakan aplikasi authenticator berbasis TOTP untuk memperkuat manajemen identitas.
  2. Enkripsi Data Sensitif: Melakukan enkripsi data sensitif pengguna (seperti nomor telepon atau data profil pribadi jika ditambahkan nanti) pada tingkat kolom database menggunakan AES-256.
  3. Logging Aktivitas Audit (Security Log): Menerapkan modul logging aktivitas administratif untuk mencatat riwayat perubahan data krusial, guna keperluan forensik apabila terjadi insiden keamanan di masa mendatang.

A. Kode Middleware IP Whitelist (`AdminIpWhitelist.php`)

<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class AdminIpWhitelist
{
    private array $allowedIps = [
        '127.0.0.1', // localhost
        '::1',       // localhost IPv6
    ];

    public function handle(Request $request, Closure $next): Response
    {
        if (! in_array($request->ip(), $this->allowedIps)) {
            abort(403, 'Akses ditolak. IP Anda tidak diizinkan.');
        }

        return $next($request);
    }
}
